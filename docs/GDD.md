# You Said Left — GDD 초안

한 명은 운전하고, 한 명은 종이 지도를 읽으며 목적지까지 도착하는 온라인 2인 협동 운전 게임.

## 문서 범위

이 문서는 플레이 경험, 역할, 게임 규칙과 개발 방향을 정리한다. 대화에서 합의한 내용은 기본 기획으로 기록하고, 추가 아이디어는 **초안 제안**, 답변이 필요한 선택은 **미정**으로 구분한다.

속도, 조작 감도, 손상 판정값, 점수 가중치, 교통량, 날씨 강도, 레벨 규모 등 조정 수치는 별도로 관리한다. GDD에는 수치 예시나 임시 기본값을 넣지 않는다. 수치 관리 형식과 저장 위치는 별도 작업에서 정한다.

## 게임 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | You Said Left |
| 장르 | 협동 운전·길 찾기 |
| 출시 목표 | PC, Steam |
| 플레이 방식 | 각자 PC에서 접속하는 온라인 2인 협동 |
| 역할 | 운전자와 조수석 |
| 목표 | 차량을 운전해 목적지에 도착하고 주행 결과를 평가받는다 |
| 진행 방향 | 쉬운 격자형 도시에서 복잡한 도로와 악천후로 확장 |

**초안 제안 — 대상 플레이어:** 친구와 대화하며 역할을 나누는 협동 플레이를 즐기는 사람. 운전 경험이나 도로 지식이 없어도 기본 안내를 통해 참여할 수 있도록 설계한다.

## 기획 의도와 핵심 플레이

자동 네비게이션이 없던 시절처럼, 지도를 해석하고 실제 도로와 대조하며 길을 찾아가는 재미를 만든다. 조수석의 설명을 운전자가 이해하고, 실제로 만난 갈림길이 지도에서 생각한 곳과 맞아떨어질 때의 성취감이 핵심이다.

- **길 찾기:** 정답 경로를 따라가기보다 표지판, 도로 모양, 주변 풍경을 근거로 위치와 방향을 판단한다.
- **역할 협력:** 운전자는 차량과 도로에, 조수석은 지도와 길 안내에 집중한다. 서로 관찰한 정보를 말로 연결한다.
- **운전의 주의 분산:** 길 안내를 듣는 동안에도 거울, 신호등, 주변 차량을 확인해야 한다.

가속·브레이크·조향은 쉽게 조작할 수 있게 만든다. 긴장감은 거울, 신호와 주변 교통을 확인하며 조수석의 안내를 듣는 데서 만든다.

### 플레이 흐름

역할과 목적지 확인 → 지도와 도로를 대조하며 주행 → 갈림길에서 방향 판단 → 목적지 도착 또는 차량 파손으로 실패 → 결과 확인

**초안 제안 — 길을 잘못 들었을 때:** 잘못된 방향 선택 자체로 바로 실패하지 않는다. 주변 정보를 다시 확인하고 경로를 수정하는 과정도 협동 플레이에 포함한다.

### 역할별 행동

| 역할 | 주요 행동 | 협력에 필요한 전달 |
|---|---|---|
| 운전자 | 가속·제동·조향, 사이드미러·백미러 확인, 신호등과 주변 차량 관찰. 지도는 열 수 없음 | 현재 도로의 모양, 표지판, 갈림길과 주변 풍경 |
| 조수석 | 창밖 관찰, 종이 지도 해석, 위치 추정, 갈 길 설명 | 진행 방향, 회전할 지점과 위치를 판단한 근거 |

조수석은 조수석 시야로 실제 도로를 보고, 필요할 때 지도를 펼친다. 차량의 실시간 위치 표시 없이 도로와 주변 단서를 지도에 대조한다. 정확한 입력 키, 시선 조작, 지도 조작 방식은 UI/UX를 설계할 때 정한다.

## 게임 시스템

### 운전

운전자는 가속·브레이크·핸들 조작으로 차량을 움직인다. 조작은 쉽게 익힐 수 있도록 구성한다. 전방뿐 아니라 사이드미러와 백미러로 주변 차량을 살피고 신호등을 확인해야 한다.

### 지도와 길 안내

지도는 조수석만 열 수 있으며, 종이 지도 방식으로 도로의 연결 관계와 목적지를 파악하는 데 사용한다. 차량의 실시간 위치나 자동 경로 안내를 제공하지 않는다. 운전자는 조수석의 설명을 듣고 주행한다.

지도와 3D 도시는 같은 청사진을 원본으로 사용한다. 튜토리얼은 사람이 청사진을 작성하고, 이후 랜덤 레벨은 생성기가 청사진을 만든다. 구김과 얼룩은 지도의 보이는 방식만 바꾸고 청사진 데이터를 바꾸지 않는다. ([ADR-001](decisions/ADR-001-blueprint-as-source-of-truth.md))

지도와 실제 도로를 대조할 수 있는 관찰 단서가 필요하다. 표지판, 도로 모양, 주변 풍경을 단서로 사용하며, 구체적인 표기와 랜드마크 구성은 레벨 설계에서 정한다.

**미정:** 지도를 펼쳤을 때의 화면 배치, 출발 위치를 처음 파악하게 하는 안내 방식.

### 일반 차량과 신호

도로에는 실제로 이동하는 일반 차량이 있다. 플레이어 차량과 충돌할 수 있으므로 주변 교통을 확인하며 주행해야 한다. 신호 위반은 기록하고 도착 후 평가에 사용한다.

**초안 제안:** 일반 차량은 차로와 신호에 따라 움직이며, 플레이어가 이동을 예상할 수 있게 한다. 교통 AI의 구현 방식은 기술 설계에서 정한다.

### 충돌과 차량 상태

차량 간 충돌은 차량 상태에 영향을 준다. 반파 등 큰 손상이 발생하면 게임 오버가 된다. 실패에 이르지 않은 차량 상태도 도착 후 평가에 반영한다.

큰 손상의 판정값은 별도 수치 관리 대상이다.

### 도착과 평가

목적지에 도착하면 신호 위반과 차량 상태를 종합해 스코어를 산출한다. 어떤 행동과 상태가 평가에 반영됐는지 결과 화면에서 확인할 수 있어야 한다.

평가 항목의 추가 여부와 목적지 도착의 구체적인 판정 방식은 미정이다. 점수 공식, 가중치와 등급 경계값은 별도로 관리한다.

## 레벨 디자인

초반에는 정사각형·직사각형 블록으로 이루어진 대도시를 사용한다. 도로 연결을 지도에서 이해하고 실제 교차로와 대조하기 쉬운 환경으로 시작한다.

튜토리얼은 해안을 따라 달리는 고정 맵으로, 갈림길과 일부 표지판을 보여주고 신호등 없이 적은 차량으로 시작한다. 튜토리얼 이후 레벨은 모두 랜덤으로 생성한다. 튜토리얼의 3D 씬은 직접 제작하고, 지도는 그 씬과 일치하도록 작성한 청사진으로 만든다. ([ADR-001](decisions/ADR-001-blueprint-as-source-of-truth.md))

진행하면서 말로 설명하기 애매한 도로 형태를 지도에 표현하고, 악천후로 관찰과 운전에 어려움을 더한다. 구체적인 도로 형태와 날씨 종류는 레벨 설계에서 선택한다.

**초안 제안 — 난도 원칙:** 초반에는 지도와 도로를 대조하는 법을 익히게 하고, 이후 갈림길의 해석과 관찰 난도를 높인다. 도로를 어렵게 만들더라도 위치를 추론할 수 있는 단서는 남긴다.

**미정:** 레벨 선택과 해금 방식. 레벨 수, 크기, 교통량과 날씨 강도는 이 문서에 정하지 않는다.

### 랜덤 지형과 도시 생성

마인크래프트의 지형 생성 기법을 참고해 변화하는 지형을 먼저 만들고, GTA 산안드레스처럼 차량으로 주행할 수 있는 도로망을 구성한다. 지상도로·경사·터널·교량·고가도로를 표현할 수 있어야 한다. 모든 맵에 모든 구조를 반드시 넣는다는 뜻은 아니다. 격자 위에서 청사진을 생성하고 Low Poly Epic City의 모듈로 3D를 조립한다. ([ADR-002](decisions/ADR-002-grid-generation-with-modular-tiles.md), [ADR-005](decisions/ADR-005-terrain-first-generation-with-tunnel-caves.md), [ADR-006](decisions/ADR-006-separate-terrain-and-grade-separated-road-network.md))

- 기본 지형을 만든 뒤 고저차와 물을 적용한다. 첫 검증부터 두 요소를 함께 확인한다.
- 높이는 정수 층과 경사 모양으로 표현한다. 물은 공통 수면부터 시작하며, 물속 바닥 높이와 수면 높이를 구분한다.
- 지형의 높이와 도로의 주행면 높이를 구분한다. 같은 수평 위치의 지하·지상·고가 구간을 함께 표현하고, 위아래로 겹친 도로는 실제 램프·접속점이 있을 때만 연결한다.
- 그래프의 접속점·교차점·경유점과 프리팹 배치를 구분한다. 모듈 배치와 상대 포트 정의를 바탕으로 접속점을 계산하고, 모듈 내부 통행과 모듈 사이 접속을 명시한다. ([ADR-007](decisions/ADR-007-node-module-placement-and-port-contracts.md))
- 출발지·목적지와 필수 경로를 계획하면서 경사·터널·교량·고가 구조에 필요한 공간을 건물 전에 예약한다. 건물 → 상세 도로·구조물 조립 → 장식 순서로 배치한다. 도로 계획과 실제 조립의 시점을 구분한다.
- 동굴의 3D 표현에는 터널 모듈을 사용한다. 차량용 터널에는 입구·내부·출구 연결과 통과할 빈 공간이 필요하다. 자연 동굴을 먼저 생성해 도로가 활용할지, 도로 계획에서 터널 구간을 정할지, 둘을 병행할지는 아직 선택하지 않았다. 자연 동굴 선생성을 채택하면 경로 계획보다 앞선 단계에 추가한다.
- 출발지에서 목적지까지의 도로 연결, 모듈 연결과 공간 조건을 각각 검사하고, 조립 이후 Play Mode와 Game View에서 실제 차량 주행을 확인한다. 종이 지도도 같은 청사진의 연결을 사용하고 입체교차를 평면 교차로로 오인시키지 않아야 한다.

Minecraft에서 가져올 구체적인 동굴·지형 생성 기법과 저장 구조는 각 단계에서 정한다. 현재 Perlin 높이 샘플러만으로 Minecraft의 전체 생성기를 구현했다고 보지 않는다. GTA 산안드레스는 주행 공간의 참고 대상이며, 해당 게임의 내부 생성 알고리즘을 채택하는 결정은 아니다. 모듈 연결 치수, 자동 경로 선택 규칙, 지도 표기와 검증 표본의 결정 시점은 ADR-006에 기록한다.

현재 구현에는 기본 지형·정수 높이·공통 수면·이웃 좌표 조회와 별도의 도로 그래프 저장·경로 조회, 논리 포트 판정·보관이 있다. 입체교차·램프는 수동 그래프 사례로 검증했으며 실제 형상·배치·공간·주행을 보장하지 않는다. 모듈 배치와 접속점 유도, 자동 도로 생성·도시 조립·종이 지도는 아직 구현하지 않았다. 정확한 현재 계약과 다음 작업은 [Blueprint API](api/blueprint.md), [청사진 작업 현황](blueprint-progress.md)에 기록한다.

### 출발 전 특성과 역할 — 제안

[ADR-003](decisions/ADR-003-trait-selection-before-random-levels.md)의 출발 전 특성 선택과 [ADR-004](decisions/ADR-004-roles-by-boarding-seat.md)의 탑승 좌석에 따른 역할 결정은 `Proposed`다. 이 문서의 확정된 플레이 흐름을 대체한 것으로 취급하지 않으며, 채택 여부와 구현을 별도로 확인한다. 특성으로 생성 파라미터를 조정하는 구체 계약은 아직 없다.

## UI/UX

| 화면 | 필요한 정보와 행동 |
|---|---|
| 접속·역할 준비 | 상대와 접속하고 운전자·조수석 역할을 확인 |
| 운전자 화면 | 주행 시야, 사이드미러·백미러, 운전에 필요한 차량 정보 |
| 조수석 화면 | 조수석에서 본 도로 시야와 필요할 때 펼치는 지도, 목적지 |
| 결과 화면 | 도착 시 신호 위반·차량 상태·종합 스코어. 실패 시 게임 오버 결과 |

**초안 제안 — 안내:** 운전 조작과 지도 읽는 법을 역할별로 설명한다. 안내가 자동 경로 탐색을 대신하지 않도록 한다.

**미정:** 게임 내 음성 채팅을 제공할지. 화면 배치와 구체적인 조작은 UI/UX 설계에서 정한다.

## 아트와 사운드

**초안 제안 — 아트 방향:** 도로의 연결, 신호, 표지판과 주변 차량을 읽기 쉬운 표현을 우선한다. 구체적인 그래픽 스타일과 배경 시대는 미정이다.

**초안 제안 — 사운드 방향:** 차량의 움직임, 제동과 충돌 상태를 소리로 전달한다. 상대의 길 안내를 듣는 데 방해가 없도록 구성한다. 음악의 분위기와 세부 효과음 목록은 미정이다.

## 기술과 제작 원칙

- Unity를 사용하며, 정확한 Editor·패키지 버전은 프로젝트 파일에서 관리한다.
- 온라인에서 같은 차량, 교통 상황과 주행 결과를 공유해야 한다.
- 접속·통신 방식, Steam 연동 범위, 차량과 교통의 동기화 방식은 기술 설계에서 정한다. GDD만으로 특정 네트워크 패키지를 확정하지 않는다.
- 게임 코드는 Unity 학습을 위해 직접 작성한다. AI는 방향 제안, 설명, 디버깅과 리뷰를 보조한다.
- 청사진 기능은 작은 테스트의 RED 확인 → 최소 구현 → GREEN 확인 → 리뷰 순서로 개발한다. 현재 구현 상태는 API와 작업 현황 문서에서 관리한다.

## 개발 단계 — 초안 제안

일정 날짜나 기간 대신, 각 단계에서 확인할 플레이 경험을 정의한다.

| 단계 | 확인할 결과 |
|---|---|
| 협동 길 찾기 | 같은 차량과 목적지를 공유하며, 운전과 지도 안내만으로 길을 찾는 재미가 있는지 확인 |
| 운전과 교통 | 거울·신호·일반 차량을 살피며 운전하는 주의 요소가 성립하는지 확인 |
| 실패와 평가 | 충돌·차량 파손·도착·평가 흐름이 납득되는지 확인 |
| 레벨 확장 | 복잡한 도로와 악천후가 협동과 길 찾기에 어떤 변화를 주는지 확인 |

## 우선 결정할 사항

이후 함께 정할 선택이다. 답변을 받으면 관련 본문에 반영하고 목록에서 제거한다.

- 지도를 펼쳤을 때의 화면 배치와 의사소통 수단.
- 잘못 든 길의 복구, 출발 위치 안내, 도착 판정과 추가 평가 항목.
- 레벨 진행 방식과 아트 방향.
