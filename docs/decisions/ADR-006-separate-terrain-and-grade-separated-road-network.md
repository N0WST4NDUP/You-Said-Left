# ADR-006: 지형과 입체 도로망을 분리하고 주행 가능한 연결을 먼저 정의한다

## 요약

> 마인크래프트의 지형 생성 기법을 참고하되, GTA 산안드레스처럼 차량으로 주행할 수 있는 도로망을 목표로 한다. 지형의 높이와 도로의 주행면 높이를 분리하고, 지상도로·경사·터널·교량·고가도로를 명시적인 연결 관계로 표현한다. 자동 생성 전에 작은 수동 청사진으로 입체교차와 램프 연결부터 검증한다.
> 이 결정은 도로 표현의 필수 계약과 작업 순서를 정한다. 구체적인 타입·API·탐색 알고리즘과 자연 동굴 생성 기법은 채택하지 않으며, 현재 지형 API가 이 계약을 이미 구현했다는 뜻이 아니다.

## 1. 요구사항 / 문제

### 관측된 사실

- 사용자는 터널·동굴이 도로 계획에서 빠져 있고 고가도로 표현이 없다는 점을 지적했다. 마인크래프트의 생성 기법을 따르면서 GTA 산안드레스처럼 실제 주행 가능한 도로를 원한다고 밝혔다. 이어 이 검토 내용을 문서에 명확히 반영하고 마지막 문서 커밋에 amend하도록 요청했다. (2026-10-08 작업 대화)
- 현재 [Blueprint](../../Assets/Scripts/Core/Blueprint/Blueprint.cs)는 `TerrainCell[,]`를 저장한다. [TerrainCell](../../Assets/Scripts/Core/Blueprint/TerrainCell.cs)은 지표 또는 물속 바닥의 절대 높이와 Grass/Water만 가진다. 같은 수평 위치의 지표·터널·고가도로를 함께 표현할 계약은 없다.
- 현재 `GetNeighborCoordinates`는 격자 안의 상하좌우 좌표를 반환한다. 도로 연결, 높이 경계나 실제 통행 가능성을 판정하지 않는다. ([Blueprint API](../api/blueprint.md))
- ADR-005는 지형 우선 생성과 터널 모듈을 이용한 동굴 표현을 결정했지만 터널 예약·배치 순서는 미정으로 남겼다. 기존 진행 기록의 평지 Grass 경로 탐색은 최종 도로 설계로 채택된 것이 아니었다. ([ADR-005](ADR-005-terrain-first-generation-with-tunnel-caves.md), 이 결정 전 작업 현황)

### 요구사항 및 제약

- **월드 목표**: 시드와 생성 설정으로 변화하는 지형을 만들고, 그 위·아래를 실제 차량이 이동할 수 있는 도로망을 구성한다. GTA 산안드레스는 원하는 주행 공간의 참고 대상이며, 해당 게임의 내부 생성 알고리즘을 확인한 근거로 사용하지 않는다.
- **연결 요구**: 출발지에서 목적지까지 이어지는 도로를 청사진에서 확인하고, 조립된 도로에서 실제 차량으로 검증한다. 지상도로뿐 아니라 경사·터널·교량·고가도로를 표현할 수 있어야 한다. 모든 생성 맵에 모든 구조가 반드시 등장한다는 요구는 아니다.
- **지도 요구**: 3D 도시와 종이 지도가 같은 연결 관계를 사용한다. 입체교차를 평면 교차로로 표시해 존재하지 않는 회전을 안내하면 안 된다. ([ADR-001](ADR-001-blueprint-as-source-of-truth.md))
- **제작 제약**: 격자와 모듈 조립을 유지하며 실제 모듈의 연결 조건을 따라야 한다. 유료 에셋 파일을 생성형 AI의 입력으로 사용하지 않는다. 게임 코드는 사용자가 작은 TDD 단계로 직접 작성한다. ([ADR-002](ADR-002-grid-generation-with-modular-tiles.md), [AGENTS.md](../../AGENTS.md))
- **이번 결정의 범위 밖**: 복셀 엔진 전체 구현, 블록 파괴·설치, 무한 월드·청크 스트리밍, 특정 Minecraft 버전의 내부 알고리즘 복제, 차로 단위 교통 AI 구현. 자연 동굴의 자동 생성 범위는 별도 미해결 항목이다.

### 결정 동인 (Decision Drivers)

- 사용자가 요구한 입체 주행 공간을 지형 격자만으로 축소하지 않을 것.
- 위치의 겹침과 실제 도로 연결을 구분해 도시와 지도에 같은 의미를 줄 것.
- 기존 지형·물 기반을 사용하면서 손코딩으로 검증 가능한 작은 단계로 진행할 것.

도로 길이, 우회, 터널·교량 사용 빈도와 생성 비용 사이의 우선순위는 아직 정하지 않았다.

## 2. 판단 근거

### 검토한 선택지

**옵션 A: 지형과 별도 입체 도로망을 두고 연결·공간 조건을 먼저 검증한다**

- 개요: 기존 지형 격자는 지표·물 정보를 담당하고, 도로망은 도로 높이와 구간·접속점을 담당한다. 터널의 빈 공간과 고가 구조의 점유·여유 공간도 구분한다.
- 채택 근거: 같은 수평 위치에 여러 높이의 통로를 표현하고, 겹침을 연결로 오인하지 않아야 한다는 요구를 반영한다. 2026-10-08 설계 검토에서 이 방향을 제안했고 사용자가 문서 반영과 amend를 요청했다.
- 감수해야 할 것: 도로 그래프, 공간 조건과 실제 모듈 조립 결과를 함께 검사해야 한다. 그래프의 도달 가능성만으로 실제 주행을 보장할 수 없다.
- 판정: **채택**. 저장 자료구조와 알고리즘 선택까지 승인된 것으로 확대하지 않는다.

### 검토했으나 배제한 방향

평지 Grass 사이 경로 찾기만으로 최종 도로 계약을 대신하지 않는다. 평지 연결은 이후 입체 도로 모델 안의 작은 사례로 검증할 수 있다. BFS 자체를 부적절한 알고리즘으로 기각한 것은 아니다.

### 근거의 한계

- Minecraft 1.18 공식 설명은 노이즈 동굴과 기존 동굴 굴착 기법의 병용, 지표와 만나는 동굴 입구, 지역 수위를 설명한다. 현재의 2D Perlin 높이 샘플러를 Minecraft의 전체 생성기로 간주할 수 없다. 어떤 생성 요소를 추가로 사용할지는 각각 설계해야 한다. ([Minecraft 공식 릴리스 설명](https://www.minecraft.net/en-us/article/caves---cliffs--part-ii-out-today-java))
- Parish와 Müller의 *Procedural Modeling of Cities*는 지형·수역 등을 도로 제약으로 사용하고, 특정 도로 구간을 표시해 기하 생성 단계에서 교량·터널 입구로 표현하는 접근을 제시한다. 도로 계획과 구조물 조립을 구분하는 참고 근거이며, 이 논문의 L-system을 프로젝트 알고리즘으로 채택한 것은 아니다. ([SIGGRAPH 2001 논문, 3.3절](https://people.eecs.berkeley.edu/~sequin/CS285/PAPERS/Parish_Muller01.pdf))
- 에셋의 터널·교량·고가·경사 모듈이 아래 계약을 모두 지원하는지, 그 연결 치수와 실제 차량 통과 여부는 이번 문서 작업에서 확인하지 않았다.

## 3. 설계

### 결정 내용

#### 지형과 도로의 책임

| 정보 | 저장·판정 책임 | 현재 구현 |
|---|---|---|
| 지표 또는 물속 바닥의 높이, 지형 종류, 수면 | 지형 데이터. 도로 배치의 환경 입력 | 기존 Blueprint API에 있음 |
| 도로의 높이·형상, 구간과 접속점, 통행 연결 | 지형과 분리한 입체 도로망. 같은 수평 위치에 여러 구간 허용 | 없음 |
| 터널의 빈 공간·덮는 지형, 구조물 점유·여유 공간 | 공간 제약과 조립 결과. 도로 종류 표시만으로 대신할 수 없음 | 없음 |
| 도시와 종이 지도 | 완성된 청사진의 지형·도로 연결·구조물 정보를 각각 표시 | 없음 |

현재 격자 `(x, y)`는 수평 좌표다. 미래 도로에서도 수평 위치와 수직 높이를 구분하며, 지형 `Level`을 도로 높이 저장 칸으로 덮어쓰지 않는다. 이 표는 미래의 책임 구분이며 새 C# 타입이나 호출 API를 정의하지 않는다.

#### 도로 구조별 조건

| 구조 | 필요한 표현과 유효성 조건 |
|---|---|
| 지상도로 | 지형 위 주행면과 접속점. 지형 경계와 실제 도로 모듈이 맞아야 함 |
| 경사·진입 램프 | 시작·끝의 높이와 방향, 중간 주행면. 높이 차이가 있다는 이유로 연결을 자동 허용하지 않음 |
| 터널 | 입구·내부 구간·출구의 연결, 차량 통과 공간과 주변 고체 지형. 모듈 배치만으로 지형 메시·콜라이더가 비워진다고 가정하지 않음 |
| 교량 | 물·골짜기 등 위의 주행면, 양 끝 접속, 구조물 점유와 여유 공간. 아래 셀이 Water라는 이유만으로 도로 연결을 차단하지 않음 |
| 고가도로·입체교차 | 아래 지형·도로와 별개인 주행면 및 공간. 위아래 도로는 연결용 램프·접속점이 있을 때만 이어짐 |

연결의 원본은 명시적인 도로 구간과 접속 관계다. 수평 인접성이나 좌표·높이의 일치만으로 접속점을 합치지 않는다. 실제 모듈을 연결할 때는 맞닿는 포트의 위치·방향·경계 높이·도로 형식의 호환성도 확인한다. ADR-002의 이웃 도로에 따른 타일 선택은 이 연결 관계를 기준으로 적용하며, 다른 높이에서 겹친 도로까지 이웃 연결로 취급하지 않는다.

#### 동굴과 차량용 터널의 구분

- **확정된 표현**: ADR-005에 따라 동굴의 3D 표현에 터널 모듈을 사용한다. 도로망은 차량용 터널의 연결과 통과 공간을 지원해야 한다.
- **아직 선택하지 않은 생성 방식**: 자연 동굴을 먼저 생성해 도로가 그 일부를 활용하는 방식과, 도로 경로를 계획하면서 터널 구간을 정하는 방식 중 무엇을 사용할지 이번 문서 정리에서 확정하지 않는다. 둘을 함께 만들지도 미정이다.
- **순서의 차이**: 자연 동굴을 도로 환경 입력으로 채택하면 동굴 공간 생성이 경로 계획보다 앞선다. 도로 계획에서 만드는 차량용 터널은 경로 계획 중에 구간·공간을 예약하고 실제 조립 단계에서 만든다. 따라서 터널 조립기의 완성이 도로 모델 설계의 선행 조건은 아니다.
- **공통 선행 조건**: 어느 생성 방식이든 차량용으로 사용할 지하 통로는 지표와 공존하고, 입구·출구에서 도로에 연결되며, 차량 통과 공간을 검사할 수 있어야 한다. 도로로 사용하지 않는 자연 동굴의 통행 조건은 이번 결정으로 확정하지 않는다. 전체 복셀 배열을 즉시 채택해야 한다는 뜻은 아니다.

#### 생성 순서

아래는 후속 생성기의 책임 순서다. 현재 실행되는 생성기는 Grass 초기화 → 높이 적용 → 공통 수면 분류뿐이다.

| 단계 | 결과와 다음 단계 진입 조건 |
|---|---|
| 지형·물 | 고저차와 수면을 가진 기본 지형. 사용할 모듈로 표현 가능한 경계와 보정 필요 여부를 검사 |
| 자연 동굴 공간 — 채택하는 경우 | 도로가 참고할 빈 공간과 입구. 생성 범위를 선택한 뒤 추가하는 조건부 단계 |
| 출발지·목적지와 필수 경로 계획·예약 | 지상·경사·터널·교량·고가 후보의 유효성을 확인하고 필요한 공간을 예약. 높이·포트·공간 조건에 맞는 목적지 연결 후보가 있어야 함 |
| 건물 | 예약한 주행 공간과 접근·조립에 필요한 공간을 침범하지 않게 배치 |
| 상세 도로와 구조물 조립 | 예약한 연결을 지키며 도로망을 구체화하고 지형 개구부·터널·교량·고가 구조를 조립. 도로와 건물의 공간 충돌 및 필수 연결을 다시 검사 |
| 장식과 지도 | 주행 공간을 침범하지 않게 장식을 배치하고 동일 청사진으로 종이 지도를 생성 |
| 최종 검증 | 데이터 도달 가능성, 모듈 연결·공간 조건, 실제 차량 주행, 지도 일치를 각각 확인 |

경로 계획은 건물보다 앞서고 도로의 상세 조립은 건물 이후에 진행한다. 예약은 수평 칸 목록만이 아니라 경사·램프·터널·교량과 주변 구조가 필요로 하는 공간까지 고려해야 한다. 예약의 구체 저장 형식은 아직 없다.

산을 우회할지, 경사로 넘을지, 터널로 통과할지, 교량·고가를 사용할지는 **후보의 주행·조립 가능 조건을 먼저 검사하고 선택 규칙으로 결정**한다. Perlin 높이만으로 이 선택이 정해지지 않는다. 유효한 필수 연결이 없는 결과를 성공 청사진으로 내보내지 않는다. 지형 보정 허용 범위, 후보 비용과 재시도 정책은 자동 생성 단계 전에 별도로 정한다.

### 변경 범위

- **추가하는 결정**: 입체 주행 목표, 지형과 도로 높이의 분리, 명시적 연결과 공간 검사, 자동 생성 전 수동 청사진 검증 순서.
- **유지하는 결정**: 청사진을 도시와 지도의 원본으로 두는 ADR-001, 격자·모듈 조립의 ADR-002, 지형 우선·터널 모듈 표현의 ADR-005. 기존 Accepted 결정 본문을 다시 쓰거나 전체 대체하지 않는다.
- **인터페이스 / 계약**: 현재 공개 Blueprint API를 변경하지 않는다. 미래 도로 데이터는 구현 시 API 문서에 추가한다. 아직 자료구조·직렬화 형식이나 데이터 마이그레이션은 없다.

### 구조

기본 지형·물과 필요시 동굴 공간을 환경 입력으로 사용해 도로 구간·접속 관계·공간 예약을 계획한다. 건물과 조립기는 그 예약을 따르고, 도시와 지도는 완성된 같은 청사진을 읽는다. 실제 클래스 구성은 이번 결정으로 확정하지 않는다.

### 되돌리기

이 문서 변경에는 게임 코드·씬·에셋·저장 데이터 변경이 없다. 구현 이후 표현 계약을 바꿀 때는 새 ADR을 작성하고, 당시 구현된 도로 데이터와 지도·조립기에 대한 이행 계획을 정한다.

### 위험과 완화

| 위험 | 대응과 확인 시점 |
|---|---|
| 위아래 도로가 평면 교차로로 합쳐짐 | 첫 수동 청사진 테스트에서 내부 연결과 층 사이 비연결을 함께 검사 |
| 그래프에는 경로가 있지만 차량은 통과할 수 없음 | 포트·주행면·충돌·여유 공간 검사 후 실제 조립 단계에서 Play Mode와 Game View 확인 |
| 터널 입구나 내부가 지형·물에 막힘 | 공간 표현과 조립 단계에서 개구부, 고체·빈 공간, 수면과 주행 공간의 관계 검사 |
| 건물·장식이 필수 통로를 침범함 | 예약 공간과 배치 충돌 검사, 각 배치 이후 필수 연결 재확인 |
| 모듈이 계획한 구조를 지원하지 않음 | 사용자의 설명·공개 자료와 사용자 Editor 조립 확인으로 연결 조건 확보, 지원하지 않는 후보는 성공 처리하지 않음 |
| 지도에 존재하지 않는 회전이 표시됨 | 입체교차·램프·터널 고정 사례를 같은 청사진의 도시와 지도에서 대조 |

## 4. 결과

> `Accepted`는 위 설계 방향의 결정 상태다. 입체 도로 구현이나 검증 완료를 의미하지 않는다.

### 검증 방법 (Confirmation)

- **첫 작은 TDD 단계**: 다른 높이에서 교차하는 두 도로를 수동으로 구성한다. 각 도로 내부에는 경로가 있고, 두 도로 사이에는 경로가 없음을 함께 검사한다. 아직 테스트 코드를 작성하거나 RED를 실행하지 않았다.
- **후속 독립 사례**: 명시적 램프 추가 후에만 층 사이 경로가 생김, 터널 입구·내부·출구 연결, 지형 높이를 덮어쓰지 않는 도로, 물 위 교량 연결, 맞지 않는 모듈 포트 거부, 터널 빈 공간과 위쪽 고체 지형 공존을 한 동작씩 검사한다.
- **자동 생성**: 예약 전후·건물 배치 후·상세 조립 후에 필수 연결과 공간 조건을 검사한다. 실패를 성공 결과로 내보내지 않는 동작도 검사한다.
- **실제 주행과 지도**: 동일 청사진에서 만든 도시와 지도에서 입체교차·램프·터널·교량을 대조한다. Play Mode와 Game View에서 차량이 연결부와 전체 필수 경로를 통과하는지 확인한다.
- **표본과 판정**: 첫 단계는 수동 고정 사례로 판정한다. 자동 생성의 시드·크기·물·높이 조합과 실제 주행 표본은 해당 단계 시작 전에 정한다. 같은 실행 환경·시드·설정에서 재현을 검사하되 플랫폼 간 일치를 현재 보장으로 쓰지 않는다.

### 측정 결과

입체 도로망·공간 표현·자동 생성·실제 주행에 대한 측정 결과 없음. 이번 작업은 문서 정리이며 기존 지형 테스트 기록을 새 도로 설계의 검증 결과로 사용하지 않는다.

### 예상과 달랐던 점

설계 검토에서 기존 다음 작업 안내가 입체 도로 계약보다 평지 경로 찾기를 먼저 제안하고, 고가도로 요구를 담지 못한 점을 확인했다. 실행 성능이나 주행 결과는 구현 전이므로 평가하지 않았다.

### 후속 조치

- Scene 지형 미리보기의 현재 상태를 확인하고 첫 수동 입체교차 사례의 타입·입력·결과를 정한다.
- 사용자 테스트 작성 → RED → 사용자 최소 구현 → GREEN → 리뷰 순서로 입체 연결 계약부터 검증한다.
- 자연 동굴을 환경 입력으로 생성할지 결정한 뒤 공간 표현을 정한다.
- 모듈 연결 조건을 확보한 뒤 공간 검사·필수 경로 예약·자동 생성·도시 조립·지도를 순서대로 확장한다.

> 필요한 것: 입체교차·램프·터널·교량 표기, 시드·크기·수면·높이 및 주행 사례의 검사 범위.
