## 요약

> 도로 노드는 그래프의 접속점·교차점·경유점으로 해석하고, 프리팹을 조립하는 모듈 배치와 분리한다. 청사진의 배치 정보와 모듈 기준 상대 정의에서 포트의 접속 위치·방향·끝점 높이 및 관련 노드 위치를 유도한다. 모듈 내부 통행과 모듈 사이 접속은 명시적 간선으로 표현한다. 만나는 경계 노드도 서로 다른 ID를 유지하며 좌표로 자동 병합하지 않는다.
> 이 결정은 #7의 값 보관 API를 최종 배치 모델로 해석하지 않도록 역할을 정한다. 새 타입·API와 포트 판정의 간선 적용은 아직 구현하지 않았다.

## 1. 요구사항 / 문제

### 관측된 사실

- [RoadNode](../../Assets/Scripts/Core/Blueprint/RoadNetwork.cs)는 ID, `Vector2Int Coordinates`, `Level`을 저장한다. ID가 다르면 좌표와 높이가 같은 노드도 저장할 수 있다. `ConnectBidirectional`은 존재하는 ID 사이 간선을 저장하고, `HasPath`는 그 간선을 탐색한다. 모듈 형상·높이 호환성은 검사하지 않는다. ([RoadNetwork API](../api/road-network.md), 기준 커밋 `1f00058`)
- [RoadPort](../../Assets/Scripts/Core/Blueprint/RoadPort.cs)는 소속 셀 주소 `CellCoordinates`, 수평 방향 `Side`, 절대 경계 높이 `BoundaryLevel`을 가진다. [RoadPortMatcher](../../Assets/Scripts/Core/Blueprint/RoadPortMatcher.cs)는 같은 경계 높이·반대 방향·바로 이웃 셀만 검사하고 간선을 추가하지 않는다.
- #7의 `AddPort(ownerNodeId, port)`는 전달한 값을 해당 ID 아래 보관한다. 노드와 포트의 좌표·높이가 달라도 저장하며 중복 값도 유지한다. [RoadNetworkTests](../../Assets/Tests/Editor/RoadNetworkTests.cs)의 좌표 불일치·경사 끝점 높이 사례는 이 보관 계약을 보호한다. 최종 모듈 소속이나 물리적 유효성의 증거는 아니다.
- [Blueprint](../../Assets/Scripts/Core/Blueprint/Blueprint.cs)의 지형 셀과 도로망은 현재 별도 데이터다. 모듈 배치, 모듈 기준 포트 정의, 포트와 경계 노드의 대응을 구성하는 기능은 없다.
- ADR-001은 교차로와 도로를 점·선 그래프로 표현하고 청사진으로 도시와 지도를 만든다. ADR-002는 도로 단위 그래프와 타일 내부 차로 경로를 구분한다. ADR-006은 지형과 입체 도로를 분리하고 좌표의 겹침을 연결로 취급하지 않는다. 이번 결정은 그 점·선과 조립 단위의 관계를 구체화한다.
- 사용자는 이번 #8 대화에서 노드·모듈·포트 분리, 배치에서 좌표 유도, 내부/외부 연결 분리와 램프 끝점 높이 표현을 추천대로 진행하고 문서화하기로 했다.

### 요구사항 및 제약

- **기능 요구**: 평지 직선·교차로, 높이가 다른 입체교차, 양끝 높이가 다른 램프를 같은 용어와 연결 규칙으로 설명해야 한다. 한 프리팹 안의 서로 연결되지 않는 통로를 하나의 노드로 합쳐 존재하지 않는 경로를 만들면 안 된다.
- **일관성 요구**: 지형 셀 주소, 모듈 배치 기준, 그래프 점과 포트 접속점의 의미를 구분한다. 좌표·높이를 중복해 보관할 때 무엇에서 유도하고 어디서 일치 여부를 검사하는지 정한다.
- **제작 제약**: 청사진을 정본으로 유지한다. 실제 모듈 지원 범위를 추정하지 않고, 작은 수동 사례와 한 동작씩의 사용자 TDD 구현으로 진행한다. ([AGENTS.md](../../AGENTS.md), [작업 흐름](../development-workflow.md))
- **품질 목표**: 성능 수치 목표는 해당 없음. 이번 범위의 판정 기준은 역할·좌표·높이·연결 책임을 수동 사례와 현재 소스에 모순 없이 대응시키는 것이다.
- **명시적 비목표**: 게임 코드·테스트 수정, 새 API 구현, 자동 도로 생성, 차로 AI, 경로 비용 최적화, 멀티셀 모듈 지원, 삭제·이동·캐시·직렬화, 실제 에셋 매핑·공간 검사·도시 조립·차량 주행.

### 결정 동인 (Decision Drivers)

위 요구에 따라 실제 연결을 설명할 수 있는 모델, 청사진의 단일 배치 원본, 손코딩으로 검증할 수 있는 작은 단계를 우선했다. 도로 비용이나 그래프 축약의 성능 이득은 이번 선택의 근거로 사용하지 않았다.

## 2. 판단 근거

### 검토한 선택지

| 선택지 | 장점과 감수할 점 | 판정과 근거 |
|---|---|---|
| 노드 하나를 도로 타일/모듈 하나로 해석하고 그 아래 포트를 둠 | 현재 #7 저장 형태와 가깝다. 하지만 단일 그래프 노드의 이웃은 서로 도달할 수 있으므로 모듈 내부의 분리된 통로를 구별할 수 없다. 배치 기준 높이와 램프 양끝 높이도 한 노드 값으로 설명하기 어렵다 | 최종 모델로 채택하지 않음. 내부 연결·입체교차·램프 요구를 별도 예외 없이 표현하기 어렵다 |
| 노드는 그래프 점, 모듈 배치와 포트는 별도이며 명시적으로 대응 | 한 모듈에 여러 점·내부 간선을 둘 수 있다. 대신 배치에서 점을 계산하고 대응을 검사하는 단계가 필요하다 | 채택. 그래프 연결과 조립 단위를 구분하면서 내부 통행을 명시할 수 있다 |
| 노드·포트의 절대 좌표를 각각 독립 편집하고 일치 검사를 수행 | 각각의 값을 직접 다룰 수 있다. 배치 이동·회전·높이 변경 때 여러 값을 함께 갱신해야 한다 | 정본 모델로 채택하지 않음. 배치와 상대 정의에서 계산할 수 있는 값을 독립 원본으로 만들지 않는다 |
| 배치 정보와 모듈 기준 상대 정의를 원본으로 삼고 해석한 값은 유도 | 이동·회전·높이의 원본을 한 곳에 둔다. 실제 모듈의 상대 정의와 변환 검증이 필요하다 | 채택. 해석한 절대 값을 보관하더라도 별도의 편집 원본으로 취급하지 않는다 |
| 맞닿는 포트의 경계 노드를 하나의 ID로 병합 | 접속부의 점을 공유할 수 있다. 모듈별 소속과 원래 ID를 다루는 병합 정책이 추가로 필요하다 | 첫 구현에서는 보류. 서로 다른 ID를 유지하고 검사 후 외부 간선을 추가한다 |

### 검토했으나 배제한 방향

- 노드와 간선, 프리팹을 각각 1:1로 강제하지 않는다. 교차로 한 모듈에 여러 내부 간선이 있을 수 있다.
- 긴 도로의 경유점들을 지금 축약하지 않는다. 우선 명시적 연결과 원래 경유점 사슬을 유지한다. 지도용 묶음이나 탐색 최적화는 후속 결정이다.
- `ConnectBidirectional`에 모든 포트·높이 검사를 일괄 추가하지 않는다. 높이가 다른 램프의 내부 간선과 같은 높이여야 하는 외부 접속은 다른 계약이다.

### 근거의 한계

단위 격자 수동 사례는 모델을 검토하는 논리 예시다. 특정 프리팹의 치수·피벗·개구부나 차량 통과를 확인한 결과가 아니다. 멀티셀 모듈은 지원 범위로 확정하지 않고 후속 과제로 남긴다. 실제 점을 저장할 C# 타입·정밀도와 Unity 변환은 아래 갭에 남긴다.

## 3. 설계

### 결정 내용

#### 역할과 대응 관계

| 대상 | 의미 | 대응 관계 |
|---|---|---|
| 지형 셀 | 수평 격자 칸의 바닥 높이·Grass/Water와 환경 정보 | 도로 연결을 소유하지 않는다. 같은 수평 주소의 여러 높이 도로와 공존할 수 있다 |
| 모듈 정의 | 조립할 모듈의 로컬 접속점·방향·끝점 높이 오프셋과 허용 내부 통행 | 여러 배치가 같은 정의를 참조할 수 있다. 실제 정의 데이터는 미구현 |
| 모듈 배치 | 사용할 모듈과 셀 주소·회전·기준 높이를 청사진에 둔 조립 단위 | 한 배치에 여러 포트와 여러 노드가 대응할 수 있다. 첫 사례는 한 셀 범위, 멀티셀은 보류 |
| `RoadNode` | 그래프의 접속점·교차점·경유점 | 프리팹이나 도로 구간 자체가 아니다. 포트가 없는 내부 교차점/경유점도 허용 |
| 경계 포트 | 모듈 밖과 만나는 주행면 끝점과 바깥 방향 | 각 포트는 해당 경계의 접속 노드에 명시적으로 대응한다. 교차로 중앙 노드에 모든 포트를 단순 부착하지 않는다 |
| 간선 | 허용된 두 그래프 점 사이 통행 | 내부 통행 또는 검사한 외부 접속을 표현한다. 프리팹 하나와 1:1일 필요가 없다 |

한 셀에 도로 배치 하나만 존재한다고 가정하지 않는다. 입체교차에서는 같은 셀 주소에 기준 높이가 다른 별도 배치를 둘 수 있다. 실제 공간이 겹치지 않는지는 별도 공간 검사 대상이다.

#### 좌표·높이의 원본과 일관성

| 값 | 설계 의미와 원본 | 현재 API와의 관계 |
|---|---|---|
| 배치 셀 주소·회전·기준 높이 | 청사진에서 편집하는 배치 원본 | 아직 없음. Scene `Transform`을 정본으로 역사용하지 않는다 |
| 포트 로컬 위치·방향·높이 오프셋 | 모듈 정의의 상대 값 | 아직 없음. 실제 모듈을 대조해 정의해야 함 |
| `RoadPort.CellCoordinates` | 포트가 속한 모듈의 논리 셀 주소 | 현재 필드는 이 주소를 저장한다. 실제 접촉 점의 좌표가 아님 |
| 해석한 포트 접속점·방향 | 배치 기준과 로컬 위치/방향을 회전·이동해서 유도 | 현재 `RoadPort`에는 실제 접속점 필드나 변환 기능이 없음 |
| `RoadPort.BoundaryLevel` | 배치 기준 높이에 해당 포트의 높이 오프셋을 적용한 끝점의 절대 높이 | 현재는 입력값 보관. 유도 기능은 없음 |
| 노드 수평 위치·`RoadNode.Level` | 그 그래프 점의 위치와 절대 주행면 높이. 경계 노드는 대응 포트의 접속점·높이에서, 내부 노드는 배치와 모듈 기준 점 정의에서 유도 | 현재 `Coordinates`는 입력 `Vector2Int` 보관. 이를 이미 셀 경계의 실제 점 표현으로 바꿨다고 해석하지 않음 |
| 지형 `TerrainCell.Level` / `WaterLevel` | 지형 바닥 / 공통 수면 | 도로의 높이와 별도 유지 |

배치에서 해석한 포트와 노드를 만드는 단계가 이 일관성을 검사한다. 경계 노드의 위치·높이는 대응 포트의 실제 접속점·끝점 높이와 같아야 한다. 내부 교차점은 경계 포트와 위치가 다를 수 있다. 해석된 절대 값을 그래프나 조립 입력에 보관하더라도 배치에서 다시 계산 가능한 값으로 다루며 독립 편집 원본을 만들지 않는다. 구체적인 저장·갱신 API는 이 문서에서 추가하지 않는다.

평지에서는 포트 높이 오프셋이 같으면 끝점 높이가 같다. 램프에서는 양끝 오프셋이 달라 각 경계 노드도 다른 `Level`을 갖는다. 배치 기준 높이 하나를 램프의 모든 노드에 복사하지 않는다. 평지의 노드 높이와 포트 높이가 우연히 같아도 각각 그래프 점과 경계 끝점을 나타내는 의미는 유지한다.

#### 내부 연결과 외부 접속

| 책임 | 판정 / 효과 |
|---|---|
| 값 보관 (`AddNode`, 현재 `AddPort`) | 현재 입력값·ID별 보관과 예외·스냅샷 계약 유지. 최종 배치 유효성을 증명하지 않음 |
| 모듈 내부 통행 정의 | 해당 모듈에서 허용한 노드 쌍만 연결. 램프처럼 높이 차이가 있는 내부 간선 허용. 분리된 통로는 연결하지 않음 |
| 논리 경계 후보 (`MatchesLogicalBoundary`) | 한 셀 논리 사례의 이웃 주소·마주보는 방향·같은 경계 높이 검사. 호출만으로 그래프 변경 없음 |
| 외부 접속을 구성하는 단계 | 논리 후보에 더해 실제 접속 위치·방향·끝점 높이·도로 형식의 호환성을 확인하고, 양쪽 경계 노드 ID 사이 간선을 명시적으로 추가 |
| 저수준 간선 저장 (`ConnectBidirectional`) / 경로 조회 | 전달한 유효 ID 사이 간선 저장 / 저장된 간선 탐색. 내부·외부 접속의 유효성을 대신 판정하지 않음 |
| 물리 배치·공간 검사와 실제 주행 | 메시·콜라이더·폭·단면·경사·차량 여유 공간을 검사하고 Play Mode·Game View에서 확인 |

맞닿는 두 경계 노드가 위치와 높이를 공유해도 ID는 별도로 유지한다. 검사 후 추가한 외부 간선이 접속을 나타낸다. 좌표가 같다는 이유로 노드를 병합하거나 간선을 추가하지 않는다. 이 외부 간선은 같은 위치의 접속 관계일 수 있으므로 도로 프리팹 하나를 반드시 요구하지 않는다.

첫 수동 사례의 통행은 양방향으로 제한한다. 차로, 일방통행, 회전 제한이나 모든 게임 도로의 양방향 정책을 확정하지 않는다. 교차로 중앙점은 이번 양방향 사례의 표현이며 차로 AI용 이동 경로와는 별개다.

#### 수동 사례

아래 좌표는 셀 중심을 정수 `(x, y)`로 놓은 **단위 격자 설명용 점**이다. 예시 경계는 중심에서 반 칸 떨어져 있다. 현재 `Vector2Int`의 저장 규격이나 프리팹 치수·피벗을 뜻하지 않는다. 표의 높이도 논리 층 예시다.

| 사례 | 배치·포트·노드 | 허용 / 거부와 이유 |
|---|---|---|
| 평지 인접 직선 | A 셀 `(2,5)`, B 셀 `(3,5)`, 두 배치 기준 높이 `1`. A의 `+X` 포트와 B의 `-X` 포트는 접속점 `(2.5,5)`, 끝점 높이 `1`로 해석. 각 포트에 별도 노드 ID를 둠 | 각 직선 내부 양끝 연결을 명시. 두 경계가 호환되면 외부 간선을 추가. 포트 소속 셀 주소는 서로 달라도 접속점은 같음 |
| 평지 교차로 | 셀 `(1,1)`, 기준 높이 `1`. 중앙 노드 `(1,1)`과 네 경계 노드 `(0.5,1)`, `(1.5,1)`, `(1,0.5)`, `(1,1.5)`. 포트는 경계 노드 각각에 대응 | 이 양방향 사례의 내부 간선은 중앙↔각 경계. 중앙은 포트가 없어도 됨. 배치 하나가 여러 노드·간선을 포함 |
| 입체교차 | 같은 셀 `(1,1)`에 아래 X방향 직선 배치 높이 `0`, 위 Y방향 직선 배치 높이 `2`. 각 배치의 양끝 포트·노드 높이는 해당 배치 높이 | 각 도로 내부 경로는 유지. 높이도 다르고 접속 관계도 없으므로 위아래 사이 간선·경로 없음. 중앙 경유점을 둬도 병합하지 않음 |
| 램프 | 셀 `(1,0)`, 배치 기준 높이 `0`. `-X` 끝점 `(0.5,0)`은 로컬 높이 오프셋 `0`, `+X` 끝점 `(1.5,0)`은 오프셋 `1`. 경계 노드 높이도 각각 `0`, `1` | 정의한 램프 내부 간선으로 높이를 연결. 왼쪽 셀 `(0,0)`의 `+X/0`, 오른쪽 셀 `(2,0)`의 `-X/1`과 각각 외부 접속 가능. 반대 끝 높이를 복사한 이웃은 거부 |
| 같은 셀·같은 높이의 여러 ID | 서로 다른 배치/통로에 별도 ID가 있고, 점의 위치와 높이까지 같을 수 있음 | 저장 가능. 내부 통행 정의나 검사한 외부 접속이 없으면 비연결. 중복 위치만으로 허용하지 않음. 실제 공간 충돌은 별도 검사 |
| 노드 위치와 포트 셀 주소가 다름 | A의 경계 노드 점 `(2.5,5)`와 소속 포트 셀 `(2,5)` | 의미가 다르므로 정상. #7 테스트의 임의 불일치 값은 보관만 보장하며, 실제 접속점과 대응 노드까지 불일치하는 입력은 구성 단계에서 거부 |
| 배치 회전 | 설명용 격자 반시계 1/4회전에서 로컬 `+X`와 오프셋 `(0.5,0)`이 `+Y`와 `(0,0.5)`로 함께 변환 | 회전 후 방향·점에 맞는 이웃과 접속. 셀 주소만 바꾸거나 방향만 회전한 상태는 거부. Unity 회전 부호·축 대응은 구현 전에 별도 확정 |

### 변경 범위

- **추가하는 결정**: 그래프 점·배치·포트의 역할, 배치 원본과 유도 값, 명시적 포트-노드 대응, 내부/외부 연결 책임, 별도 ID와 외부 간선.
- **유지하는 결정**: ADR-001의 청사진 원본, ADR-002의 격자·모듈 조립과 도로 그래프/차로 경로 구분, ADR-006의 지형·입체 도로 분리와 공간·주행 검증. 기존 Accepted 본문은 결정 당시 기록으로 보존한다.
- **현재 인터페이스**: 변경 없음. 현재 #7 API는 보관 계약이다. 최종 모델의 구현 시 모듈 소속과 경계 노드 대응, 점의 표현·유도 API를 정하고 관련 테스트를 한 동작씩 추가한다.
- **에셋 조사 지침의 변경**: 사용자는 이번 대화에서 `AGENTS.md`의 유료 에셋 AI 조사 제한을 삭제하고 `Imported`를 직접 찾아 대조하도록 지시했다. ADR-002·005·006과 #8 이슈의 과거 조사 제한은 현재 작업 지침으로 재적용하지 않는다. 현재 조사 범위는 [AGENTS.md](../../AGENTS.md)와 사용자의 직접 지시를 따른다. 에셋은 기존대로 Git에서 제외하며 관찰과 실제 주행 검증은 구분한다.

#### 현재 API·테스트에 대한 후속 영향

| 현재 대상 | 후속 구현에서 확인할 범위 |
|---|---|
| `RoadNode.Coordinates`와 노드 값 보관 테스트 | 접속점 표현의 구체 타입·단위를 결정하고, 배치에서 유도한 점과 경계 노드의 일치 사례 추가. 현재 정수 입력 보관 테스트를 새 좌표 규격의 검증으로 해석하지 않음 |
| `RoadPort` 및 `AddPort` / `GetPorts`, `RoadNetworkTests`의 #7 사례 | 모듈 배치 소속과 포트-경계 노드 대응을 표현하는 계약 추가. 현재 누락 ID·중복·불일치 보관·스냅샷·상태 보존은 저수준 계약으로 유지. 소속 API의 이행·대체가 필요한지는 해당 구현 범위에서 결정 |
| `RoadPortMatcher` / `RoadPortTests` | 기존 한 셀 논리 경계 회귀 유지. 배치 회전·높이에서 해석한 값과 실제 접속점/형식의 호환성 검사는 별도 사례로 추가 |
| `ConnectBidirectional` / `HasPath`와 수동 그래프 사례 | 기존 명시적 간선 저장·도달 계약 유지. 내부 통행과 검사한 외부 접속을 구성한 결과, 거부 후 상태 보존과 층 사이 비연결을 추가 검증 |

이 표는 코드 수정 명령이 아니다. 새 타입·메서드 이름과 기존 API의 최종 이행 방식은 아직 정하지 않았다.

### 구조

모듈 정의 + 청사진 배치 → 해석한 포트·그래프 점과 명시적 대응 → 허용 내부 간선 + 검사한 외부 접속 간선 → 도로망. 도시 조립과 지도는 같은 청사진을 읽는다. 이는 합의한 데이터 흐름이며 실제 클래스가 모두 존재한다는 뜻이 아니다.

### 되돌리기

이번에는 문서만 변경하며 코드·씬·저장 데이터 이행은 없다. 구현 후 이 역할이나 좌표 원본을 바꿀 경우 새 ADR과 해당 시점 API·데이터의 이행 계획을 작성한다.

### 위험과 완화

| 위험 | 대응 |
|---|---|
| 현재 노드 ID별 포트 목록을 최종 모듈 소속으로 오해 | API·작업 현황에 현재 보관과 미래 대응을 분리해 기록 |
| 배치·포트·노드의 절대 값을 독립 변경해 어긋남 | 배치와 로컬 정의에서 유도하고 경계 노드 대응을 검사 |
| 단일 모듈 노드가 분리된 통로를 이어 버림 | 여러 점과 허용 내부 간선을 명시하고 입체교차 비연결 검증 |
| Matcher 통과를 물리 주행 성공으로 해석 | 논리 후보, 실제 포트 호환, 공간 조건과 차량 주행을 단계별 검증 |
| 같은 위치의 외부 간선을 도로 길이/지도 선분으로 오해 | 접속 간선과 모듈 내부 구간의 역할을 보존. 비용·지도 표현은 후속 단계에서 정함 |

## 4. 결과

> `Accepted`는 역할과 계약에 대한 사용자 합의다. 새 모델의 구현·테스트·조립·차량 주행이 완료됐다는 뜻이 아니다.

### 검증 방법 (Confirmation)

- **이번 문서 범위**: #8 질문·완료 조건과 현재 소스/API를 대조한다. 위 수동 사례에서 소속·점·높이·내부/외부 간선을 구분할 수 있는지 리뷰하고, 문서 간 일치·링크·형식·diff를 검사한다.
- **문서 검증 기록 (2026-10-11)**: 현재 소스·#8 본문과 문서를 대조했고 독립 리뷰에서 수정이 필요한 모순·누락을 찾지 못했다. 상대 링크·헤딩 앵커·표 열 수·코드 블록·갭 개수 검사와 `git diff --check`를 통과했다. 새 모델의 실행 결과로 해석하지 않는다.
- **후속 TDD**: 아래 목록에서 한 동작만 선택해 테스트 작성 → RED → 사용자 최소 구현 → GREEN → 리뷰를 반복한다. 기존 구현의 회귀 사례는 바로 GREEN이어도 그대로 기록한다.

| 순서 후보 | 관찰할 동작과 기대 결과 |
|---|---|
| 첫 범위 | 한 셀 배치와 로컬 포트에서 소속 셀·접속점·방향·끝점 높이를 유도. 먼저 무회전 한 사례, 이후 회전·높이 사례를 한 동작씩 추가 |
| 경계 노드 대응 | 대응 포트와 같은 점·높이를 얻음. 셀 주소와 점이 다를 수 있음을 확인하고 실제 대응 불일치는 거부 |
| 내부 통행 | 직선·교차로의 명시한 내부 경로만 존재. 분리된 통로 사이에는 경로 없음 |
| 외부 접속 | 호환하는 두 포트의 서로 다른 노드 ID 사이에만 간선 추가. 후보 등록·Matcher만으로 간선 없음, 거부 후 기존 상태 유지 |
| 램프·입체교차 | 램프 양끝은 다른 높이, 각 외부 끝은 이웃과 같은 높이. 위아래 도로는 내부 경로 유지·상호 비연결, 램프를 명시한 뒤에만 경로 생성 |

이 표는 테스트 코드나 실행 결과가 아니다. 구체적인 첫 API·점 타입·오류 계약과 독립 범위를 다음 구현 시작 전에 좁힌다. 첫 구현에서는 멀티셀 모듈·비용 최적화·차로 AI를 함께 추가하지 않는다.

### 측정 결과

해당 없음 — 새 모델을 구현하거나 측정하지 않았다. 기존 #7 테스트의 실행 기록은 [RoadNetwork API](../api/road-network.md#실행-기록)와 [작업 현황](../blueprint-progress.md)에 날짜와 범위를 구분해 보존한다.

### 예상과 달랐던 점

구현 전이라 새 모델의 부작용은 관측하지 않았다. 현재 `Vector2Int` 입력 보관만으로는 설명용 반 칸 경계 점을 표현할 수 없으며, 이 차이는 첫 구현 전 결정할 표현 갭이다. 기존 노드별 포트 목록도 최종 배치 소속을 대신하지 못한다.

### 후속 조치

다음 세션에서는 최신 Git·소스와 이 결정을 확인한 뒤 첫 포트 유도 동작의 범위를 정한다. 현재 보관 계약을 일괄 수정하지 말고, 필요한 API·테스트 변경을 해당 동작의 완료 조건과 함께 정한다. 공간 검사·터널 조립·실제 주행은 별도 후속 범위다.
