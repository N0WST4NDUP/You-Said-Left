# ADR-005: 지형을 먼저 생성하고 동굴을 터널 모듈로 표현한다

## 요약

> 랜덤 도시 청사진을 만들 때 마인크래프트처럼 변화하는 지형을 바탕으로 도시를 구성한다. 지형의 높이와 물을 먼저 생성하고, 그 결과에 맞춰 출발지·목적지, 건물, 도로와 장식을 배치한다. 동굴은 Low Poly Epic City의 터널 모듈로 표현한다.
> 이 결정은 생성 방향과 표현 방법을 정한다. 마인크래프트의 내부 알고리즘이나 전체 기능을 재현한다는 뜻은 아니며, 현재 높이 격자만으로 지하 공간과 터널 연결까지 표현할 수 있다고 가정하지 않는다.

## 1. 요구사항 / 문제

### 관측된 사실

- 청사진이 3D 도시와 종이 지도의 원본이다. ([ADR-001](ADR-001-blueprint-as-source-of-truth.md))
- 도시를 격자 위에서 생성하고 Low Poly Epic City의 모듈로 조립한다. ([ADR-002](ADR-002-grid-generation-with-modular-tiles.md))
- 현재 구현은 격자의 지형 종류와 정수 높이를 저장하며, 생성기는 높이를 적용한 뒤 공통 수면보다 낮은 셀을 물로 분류한다. ([Blueprint API](../api/blueprint.md), [생성기](../../Assets/Scripts/Core/Blueprint/BlueprintGenerator.cs))
- 사용자는 마인크래프트와 비슷한 생성을 원하며, 에셋의 터널을 동굴 표현에 사용하겠다고 밝혔다. 이 문서에서는 사용자의 설명을 근거로 하고 에셋 파일을 다시 조사하지 않았다. (청사진 작업 대화, 아래 부록)

### 요구사항 및 제약

- **기능 요구**: 지형을 먼저 만들고 도시 배치가 그 지형을 따르게 한다. 첫 검증부터 고저차와 물을 포함한다. (사용자)
- **표현 요구**: 높이는 정수 층과 경사 모양으로 표현하고, 한 층은 6 Unity 단위로 조립하는 방향을 사용한다. 동굴은 터널 모듈로 표현한다. (사용자가 선택한 높이 표현 및 동굴 표현)
- **연결 요구**: 출발지에서 목적지까지 도로가 연결되는지 여러 생성 결과로 검사할 수 있어야 한다. (사용자의 최초 생성기 요구)
- **제약**: 생성 결과는 에셋으로 조립 가능한 모양이어야 한다. 에셋 파일을 생성형 AI 도구의 입력으로 사용하지 않는다. (ADR-002)
- **이번 결정의 범위 밖**: 복셀 저장 구조, 블록 파괴·설치, 무한 월드·청크 스트리밍, 바이옴, 터널 연결 알고리즘의 채택 여부. 이 결정만으로 이 기능들을 확정하지 않는다.

### 결정 동인 (Decision Drivers)

- 사용자가 원하는 마인크래프트와 비슷한 지형 생성 방향을 유지할 것.
- 도시를 만들기 전에 고저차와 물을 확인할 수 있을 것.
- 이미 선택한 도시 모듈을 활용할 것.

동인 사이의 추가 우선순위는 정하지 않았다.

## 2. 판단 근거

### 검토한 선택지

**옵션 A: 지형 우선 생성과 터널 모듈을 이용한 동굴 표현**

- 개요: 높이와 물이 있는 지형을 먼저 만들고 도시를 배치한다. 동굴의 3D 표현은 터널 모듈을 사용한다.
- 채택 근거: 사용자가 지형 우선 순서, 첫 고저차·물 검증, 터널을 이용한 동굴 표현을 선택했다. ADR-002의 모듈 조립 방향을 이어간다.
- 감수해야 할 것: 정수 높이만으로 경사 방향이나 지하 연결이 정해지지는 않는다. 터널 입구와 높이, 주변 지형의 관계를 별도로 설계하고 검증해야 한다.
- 판정: **채택**.

### 검토했으나 배제한 방향

이 작업에서 별도의 대안을 비교·기각한 기록은 없다. 마인크래프트와 같은 복셀 엔진이나 특정 동굴 노이즈 알고리즘을 검토해 기각했다고 기록하지 않는다.

### 근거의 한계

- 터널 모듈 사용은 사용자의 설명에 따른 결정이다. 이번 문서화 작업에서 터널 프리팹의 치수, 연결 포트나 실제 주행을 검증하지 않았다.
- 현재 구현은 좌표마다 지표 또는 물속 바닥의 높이 하나를 저장한다. 같은 수평 좌표의 지표와 터널, 터널 내부 빈 공간을 모두 저장하는 계약은 없다.
- 공통 수면 방식은 바다와 호수의 첫 표현이다. 물의 흐름이나 바다·호수의 구분, 강 생성은 구현하지 않았다.

## 3. 설계

### 결정 내용

- 기본 Grass 격자를 만든 뒤 높이와 물을 적용한다.
- 샘플러가 정수 높이 오프셋을 계산하고, 생성기는 이를 기준층에 더해 절대 높이 층으로 저장한다. 현재 Perlin 샘플러의 노이즈 양자화는 `TerrainLevelQuantizer`가 담당한다. 청사진은 계산된 결과를 저장한다.
- 현재 공통 수면 단계에서 `TerrainCell.Level`은 땅 또는 물속 바닥의 절대 높이 층이고, `Blueprint.WaterLevel`은 수면의 절대 높이 층이다. 수면보다 낮은 셀만 자동으로 Water가 된다.
- 이후 출발지·목적지를 정하고, 건물로 필수 연결을 막지 않도록 경로 후보를 예약한 뒤 건물을 배치하는 방향을 사용한다. 실제 도로 모양과 연결 검증은 도로 생성 단계에서 구체화한다.
- 도로와 장식은 지형 및 앞 단계의 배치를 기준으로 만든다.
- 경사는 높이 층에 더해 모양과 방향을 표현한다. 이웃의 높이 차이가 한 층이라는 사실만으로 주행 가능하다고 처리하지 않는다.
- 동굴은 터널 모듈로 표현한다. 입구, 지하 경로, 지표와 겹치는 경우의 청사진 표현 및 지도 표기는 터널 단계에서 정한다.

### 변경 범위

- **추가하는 결정**: 지형 우선 생성 순서, 정수 높이 층과 경사 표현, 동굴의 터널 표현.
- **유지하는 결정**: 청사진을 도시와 지도의 원본으로 두는 ADR-001, 격자와 모듈형 타일로 조립하는 ADR-002. 두 ADR을 대체하지 않는다.
- **인터페이스 / 계약**: 현재 공개 API와 미래 데이터 구조는 [Blueprint API](../api/blueprint.md)에서 구분한다. 현재 지형 격자는 ADR-001의 도로 그래프를 구현한 것이 아니다.

### 구조

현재 코드의 생성 순서는 `Grass 초기화 → 높이 적용 → 공통 수면 적용`이다.

도시 생성의 후속 방향은 `출발지·목적지와 필수 경로 예약 → 건물 → 도로 → 장식`이다. 터널의 예약·배치가 어느 단계에 들어갈지는 아직 정하지 않았다. 조립기와 지도는 완성된 청사진을 읽으며, 각자 별도로 지형을 다시 생성하지 않는다.

### 되돌리기

- 이 결정으로 코드나 데이터 형식을 변경하지 않는다. 경사와 터널은 아직 구현되지 않았다.
- 생성 방향을 바꾸면 새 ADR로 이 결정을 대체한다. 현재 지형 API와 미래 조립기·지도에 미치는 영향은 변경 시점에 확인한다.

### 위험과 완화

| 위험 | 확인 또는 대응 방향 |
|---|---|
| 노이즈 높이의 경계를 경사 모듈로 조립할 수 없다 | 높이 경계·모양·방향과 모듈 연결 조건을 함께 정하고 검사한다. 구체 규칙은 미정이다 |
| 터널이 지표나 물, 다른 구조물과 충돌한다 | 터널 데이터와 배치 제약을 설계할 때 확인한다. 현재는 충돌 방지 규칙이 없다 |
| 건물이 필수 도로 후보를 막는다 | 건물 전에 필수 경로를 예약하는 방향으로 설계한다. 예약 자료구조와 알고리즘은 미정이다 |
| Scene 미리보기를 실제 주행 검증으로 오해한다 | 지형 데이터 테스트, Scene 확인, Play Mode와 Game View의 조립·주행 확인을 구분한다 |

## 4. 결과

> Status가 `Accepted`이므로 검증 계획을 기록한다. 전체 도시와 터널의 구현·검증이 끝났다는 뜻은 아니다.

### 검증 방법 (Confirmation)

- **지형과 물**: Editor 테스트로 샘플링 결과의 정수 높이 적용, 수면 경계, 물속 바닥 높이 유지와 같은 입력의 재현을 검사한다. Scene 미리보기로 높이 변화와 공통 수면을 확인한다.
- **도로 연결**: 출발지에서 목적지까지 경로가 존재하는지 청사진 데이터로 검사한다. 경사·터널 도입 후에는 모양, 방향과 연결 높이도 함께 검사한다.
- **도시와 지도**: 실제 조립 단계에서 Play Mode와 Game View로 도로·터널 주행과 청사진·지도 일치를 확인한다.
- **검증 구간과 표본**: 사용할 시드 수, 크기 조합, 경사·물·터널 사례는 후속 검증 계획에서 정한다.
- **판정 기준**: 높이·물 계약을 지키고, 생성한 도로가 목적지까지 연결되며, 실제 모듈 연결과 지도 표현이 청사진과 일치해야 한다. 경로 길이 등 추가 기준은 아직 정하지 않았다.

### 측정 결과

전체 결정에 대한 측정 결과 없음 — 현재 지형 API와 디버그 표시 코드의 범위는 [작업 현황](../blueprint-progress.md)에 기록한다.

### 예상과 달랐던 점

전체 도시와 터널을 생성하지 않았으므로 아직 평가하지 않았다.

### 후속 조치

- Scene에서 현재 지형·수면 미리보기를 확인한다.
- 도로의 첫 연결 테스트와 경사 표현 계약을 정한다.
- 터널의 청사진 데이터, 연결 및 지도 표기를 정한다.
- 생성 결과 검증의 표본과 세부 판정 기준을 정한다.
